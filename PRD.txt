# Weekly Football Stats Tracker

## Product Requirements & Design Document (PRD v1)

---

# 1. Project Overview

## Project Name

**Weekly Football Stats Tracker**

## Objective

Develop a web application that allows a football group to record weekly matches, automatically track player statistics, maintain match history, and generate leaderboards with minimal manual input.

The system is designed around the principle that **the only information entered during a game is the scoring event**. All scores, winners, and player statistics are calculated automatically.

---

# 2. Problem Statement

Currently, weekly football statistics are difficult to maintain because:

* Goals are forgotten after matches.
* Individual player records are lost.
* Match history is unavailable.
* Team performance cannot be reviewed.
* Maintaining statistics manually is time-consuming.

The objective is to create a simple system that requires very little data entry while producing detailed statistics.

---

# 3. Goals

* Track every player's goals.
* Track games played.
* Store every football session.

* Generate automatic leaderboards.

# 5. No Goal Override

If no goal is scored within the predefined time limit (for example 10 minutes):

* No player goal is recorded.
* Current winning team remains on the field.
* Waiting team rotates normally.
* Rotation is updated manually using a **No Goal / Time Up** action.

This is the only gameplay override required.

---

# 6. Core Design Principle

The application is **event-driven**.

Only events are stored.

Everything else is calculated.

Examples of events

* Goal
* No Goal / Time Up
* Session End
* Undo Last Event

Scores, winners, player statistics, and leaderboards are generated from these events.

# 19. Success Criteria

The project is considered successful if:

* A complete football session can be recorded in under two minutes of total data entry.
* All player statistics are generated automatically.
* No manual score calculation is required.
* Both game formats are fully supported.
* Historical data remains accessible for every session.
