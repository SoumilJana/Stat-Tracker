# Database Design Document (DDD)

## Weekly Football Stats Tracker

Version 1.0

---

# 1. Database Philosophy

The database follows an **Event Sourcing** approach.

Instead of storing calculated values, the database stores **facts**.

Examples of facts:

* Player was created
* Session started
* Player assigned to Team A
* Soumil scored
* Session ended
* Timeout occurred

Everything else is calculated.

# 3. Tables

## Players

Stores permanent player information.

| Column        | Type               |
| ------------- | ------------------ |
| id            | UUID               |
| name          | TEXT               |
| jersey_number | INTEGER (nullable) |
| photo_url     | TEXT               |
| created_at    | TIMESTAMP          |

Notes

* One record per player.
* Never deleted (soft delete can be added later).

---

## Sessions

Each football day is one Session.

| Column     | Type                          |
| ---------- | ----------------------------- |
| id         | UUID                          |
| date       | DATE                          |
| location   | TEXT                          |
| mode       | ENUM (STANDARD, WINNER_STAYS) |
| notes      | TEXT                          |
| started_at | TIMESTAMP                     |
| ended_at   | TIMESTAMP                     |

Example

```
Session #14

7 Aug 2026

Winner Stays
```

---

## Teams

Teams only exist inside a session.

| Column     | Type |
| ---------- | ---- |
| id         | UUID |
| session_id | UUID |
| team_name  | TEXT |
| team_color | TEXT |

Example

```
Session 15

Team A

Team B

Team C
```

---

## SessionPlayers

Assigns players to teams for a specific session.

| Column     | Type |
| ---------- | ---- |
| id         | UUID |
| session_id | UUID |
| player_id  | UUID |
| team_id    | UUID |

Example

```
Session 15

Soumil

Team A
```

A player can appear only once in a session.

---

## GoalEvents

The heart of the application.

Every goal equals one row.

| Column     | Type      |
| ---------- | --------- |
| id         | UUID      |
| session_id | UUID      |
| team_id    | UUID      |
| player_id  | UUID      |
| created_at | TIMESTAMP |

Example

```
Goal #51

Session 14

Player

Soumil

Team

Red

Time

18:24:15
```

---

## SessionEvents

Stores non-goal events.

| Column     | Type      |
| ---------- | --------- |
| id         | UUID      |
| session_id | UUID      |
| event_type | ENUM      |
| metadata   | JSONB     |
| created_at | TIMESTAMP |

Possible events

```

SESSION_ENDED

TIMEOUT

UNDO

```

# 5. Derived Statistics

Never stored.

Calculated using SQL.

Examples

Total Goals

```
COUNT(goal_events)
GROUP BY player
```

Games Played

```
COUNT(session_players)
GROUP BY player
```

Goals Per Game

```
Goals

÷

Games Played
```

Golden Boot

```
ORDER BY

Goal Count DESC
```

# 11. Constraints

Player name required.

A player may belong to only one team in a session.

GoalEvents require

* valid player
* valid team
* valid session

Sessions cannot be deleted after ending.

# 13. Why Event Sourcing?

Advantages

* Complete history
* Easy Undo
* Automatic statistics
* AI can replay matches
* Future analytics
* Reliable auditing
* Supports new features without redesigning the database

The event log becomes the single source of truth.
